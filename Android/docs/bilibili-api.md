# B 站搜索、播放和下载

本文依据 Android 当前实现。入口是「在线搜索 → B站」，音频库「导入 → 导入在线音频」切换到在线搜索并恢复原页面状态；不传入原文件夹，保存的内容放音频库根目录。

## 搜索和输入

「视频 / UP主」各自保留输入和结果；「作品 / B站 / YouTube」分别保留输入、结果和滚动位置。UP 主投稿在搜索页内展开，按返回先退出选择或投稿列表，原搜索位置保留。

`BiliSearchInput` 先识别 BV 号（也支持链接／分享文字中的 BV），再识别 `space.bilibili.com/{uid}` 主页链接或 `UID:数字`。纯数字仅在 UP 主模式作为 UID，视频模式仍按关键词搜索。昵称只在 UP 主模式搜索；主页链接校验真实主机名，不接受相似域名。

现有 `BilibiliClient` 新增：

- `searchVideos(keyword, page, order, duration)`：返回 `BiliPage<BiliVideoHit>`，包含 BV、标题、作者、封面、时长和作者 UID。
- `searchUploaders(keyword, page)`：返回 `BiliPage<BiliUploader>`，包含 UID、昵称、头像、简介、粉丝数和投稿数。
- `uploaderVideos(mid, page)`：返回该 UP 主最新投稿的视频页。UID 直达时标题使用 UID；未取得资料不伪造昵称、头像和粉丝数。
- `videoDetails(input)`：复用 `/x/web-interface/view`，返回视频本身的标题、封面、分 P 和可空的所属合集 `collection`，供预览及播放页合集跳转使用；原标题不混入第一 P 的名称。
- 原有 `lookup(input)` 继续返回 `List<BiliPart>`，包含每个分 P 的 BV、CID、页码、标题、作者、时长和封面，供播放、保存及下载使用。

从剪贴板识别到 BV 时先显示标题和封面；单 P 视频按钮显示「导入」，多 P 视频才显示「选择入库方式」，后续复用搜索、收藏夹和搜索下载的入库流程。多 P 必须选分开或统一；已保存的视频也可以在转换确认后调整组织方式。取消不创建入库记录或下载任务。

## 请求与分页

请求复用已有 B 站登录、匿名 buvid／ticket 和 WBI 签名，不增加登录方式或外部搜索服务。搜索解析使用 Kotlin 序列化，不依赖 Android 的 `org.json`。标题去除搜索高亮 HTML 标签，封面统一为 HTTPS，时长转为毫秒。

- `GET https://api.bilibili.com/x/web-interface/wbi/search/type`：`search_type=video` 或 `bili_user`、`keyword`、`page`、`page_size=20`。视频排序为 `BiliVideoOrder`：`totalrank`（默认）、`click`、`pubdate`、`dm`、`stow`、`scores`；时长为 `BiliVideoDuration`：`duration=0`（默认全部）、`1`（10 分钟以下）、`2`（10–30 分钟）、`3`（30–60 分钟）、`4`（60 分钟以上），边界由 B 站判断。用户搜索固定 `order=0`，不传视频时长。两个新增参数都有默认值，原调用保持兼容。
- `GET https://api.bilibili.com/x/space/wbi/arc/search`：`mid`、`pn`、`ps=30`、`order=pubdate`，从 `data.list.vlist` 读取投稿，按 `data.page.count` 判断后续页。
- 以上参数经 `WbiSigner` 添加 `wts` 和 `w_rid`。错误码 `-403` 刷新 WBI 密钥后最多重试一次，其余错误不自动重复搜索。Referer 使用搜索页或指定 UP 主主页。
- `GET https://api.bilibili.com/x/web-interface/view?bvid=...`：读取分 P。搜索、投稿和分 P 浏览的主体请求都可随协程取消关闭 HTTP。

视频搜索框下提供排序和时长下拉入口，只作用于关键词搜索；BV 直达不应用视频筛选。筛选改变且输入非空时取消旧请求、清除选择及结果、重新请求第一页并回顶，空输入时只更新选项。查询提交时固定关键词和筛选快照，追加分页与失败重试不读取变化中的界面选项。切来源、切模式及详情返回保留筛选与列表位置；重启恢复默认值。UP 主搜索、投稿和合集不变。

滚动加载时按 BV／UID 去重，重复页没有新项目时停止自动读取；失败保留已有项目与下一页编号，重试仍请求同一页。新查询、切换视频／UP 主模式、打开其他 UP 主时取消旧请求，并检查请求编号，防止迟到响应覆盖新结果。中止后暂停自动分页，手动「加载更多」才继续。

接口需要登录、访问受限、网络异常与空列表分别处理。HTTP 412、API `-412` / `-352` 等显示访问限制；不把 HTML 错误页或缺少列表的数据当成“没有投稿”。不记录 Cookie、请求头、完整媒体地址或接口正文。

## 登录与自动续期

扫码登录后 Cookie 与 refresh token 存入加密偏好，约每 20 小时通过 `x/passport-login/web/cookie/info` 判断是否需要续期；需要时依次请求 `correspond/1/`、`cookie/refresh` 与 `confirm/refresh`，保存新会话后确认旧 token 作废。确认失败只记日志，会话已保存不算续期失败。

续期任一步失败（缺少 csrf、解析不出 refreshCsrf、服务端拒绝、拿不到新 csrf）都不标记「已检查」，改为记录失败时间。失败后 10 分钟内不再尝试，避免离线或凭证失效时每次 B 站请求都打网络；读取 `cookie/info` 异常同样进入这段冷却。冷却结束或距上次成功检查超过 20 小时后再次尝试。「我的」页在可续期且处于失败状态时显示「自动续期失败，请重新登录」；续期成功、粘贴新凭证、重新扫码或退出登录都会清除失败标记。日志只输出响应码与异常类名，不记录 Cookie、token 或接口正文。

## 视频和分 P 操作

点视频只播放这一首：单 P 直接播放，多 P 弹窗单选；不会保存曲目或把整页结果放入队列。多 P 保存或下载先选择分开或统一，分开导入默认全选，可逐 P 取消，统一导入包含全部 P。所有入库入口共用这一个选择弹窗：已有选择未完成时，其他入口立即提示「请先完成当前的入库选择」并返回，不持锁等待用户，也不静默排队；确认或取消后新的选择可以正常登记。长按支持视频多选、全选、批量保存和下载；先汇总读取所选视频的分 P，再在按视频分组的清单中确认。读取失败的项目单独展示，其余项目仍能执行。

已保存内容使用原曲目。未保存内容使用远端队列，`source=BILIBILI`、`workno=bvid`、`fileKey=cid`、`remoteUrl` 保存稳定观看页地址或已有本地缓存路径；转成媒体条目时按 BV/CID 生成 B 站 DASH 音轨清单，不把观看页交给音频解码器，不保存临时 CDN 地址。已有缓存优先本地播放，字幕仍按 BV/CID 查找。

保存使用 `BiliImportRequest` 和 `BiliLibraryStore`，以 BV/CID 复用曲目；普通重复保存保留位置，明确确认转换后才调整归属，保留原编号及字幕、队列、下载和播放列表关联。显示已保存、已下载和正在下载的分 P 数量，不根据部分分 P 推断整部视频已处理完。

## 播放页所属合集入口

视频详情 `/x/web-interface/view` 的 `data.ugc_season` 直接提供所属合集。从首个非空章节的第一条视频读取 `arc.pic` 作为合集封面，忽略 `ugc_season.cover`，也不使用当前播放视频封面代替首视频。解析 `id`、`title`、`mid`、`intro`、`ep_count` 为 `BiliCollectionKind.SEASON`；`mid` 缺失时使用视频 `owner.mid`。缺少有效编号、UP 主身份或标题时不生成入口，不根据本地系列成员或标题推断归属。

`videoDetails` 成功后将所属合集及明确的无合集结果写入最多 64 项的会话内缓存。播放页复用这份信息；旧曲目尚未读取详情时，在独立协程中补查，多个播放界面共享同一次补查。请求失败不缓存为“没有合集”，也不影响播放和字幕；切换曲目或账号会取消旧的补查等待。

当前曲目通过已入库队列的 `bvid`，或未入库队列的 `workno` 取得视频身份。入口状态同时绑定 BV，切歌、切到其他来源或清空队列时不能显示上一视频的合集。按钮使用「合集：标题」，长标题两行省略，点击复用现有合集详情路由，不自动收藏、入库、下载或修改队列，返回保留播放页。

此信息不增加数据库列，也不写入凭证或媒体临时地址。退出应用后，旧曲目首次打开时可重新读取详情；离线且会话内尚无归属信息时隐藏入口。

## 统一视频项与转换

统一视频项用独立 B站目录身份承载，复用标题和封面字段，不伪造曲目或 DLsite/asmr.one 身份。根目录、「B站」筛选和搜索只展示一次该视频，内部 P 不重复作为根条目出现；命中 P 的搜索结果归并到分组，目录搜索不会归并到范围外祖先。视频卡片显示 UP 主及「多P」标签，卡片和详情页的「B站」标签与普通音轨共用 `LocalSourceColors.bilibili` 配色；独立页面按 page、id 排序，支持多选播放、队列、下载、播放列表及下载副本删除，单项和批量移除在界面与仓储层均受限制。

分开与统一可确认后转换；统一时归并这个 BV 全部已入库 P 并补齐当前请求，拆分时先将原组全部已有 P 放回其父目录，再删除空分组。未勾选的已有 P 保留。升级不自动转换已有内容，所有新内容保存到音频库根目录。

## 下载成功后入库

`DownloadCenter.enqueueBili(parts, autoImport = false)` 保持原默认行为：收藏夹「下载音轨」不自动加入音频库，反馈按新增分 P 任务和失败视频分别计数。搜索页通过 `enqueueBiliImports(requests)` 持久化入库批次后排队，确认前不创建任务。

数据库版本为 17。13→14 添加的 `downloads.biliImportPart` 继续兼容旧 BiliPart JSON；新的批次元数据包含 part 和 batchId。15→16 添加可空、唯一的 `folders.biliBvid`（无 DEFAULT），以及 `bili_import_intents` 表，按 BV 持久化当前 batchId 和请求 JSON；内容包含方式、视频信息、目标 P 和转换确认，不包含临时媒体地址或登录信息。旧记录为 null 时仍仅缓存。

`BiliDownloads` 在事务中按 BV/CID 去重。同一分 P 已有排队／运行任务时补充入库元数据，不新建任务；工作者完成时重新读取元数据。已有完整缓存时直接保存并关联完成记录；失败重试仍保留入库意图。用户识别挂上的本地文件也不会额外下载。

新的入库请求与任务创建按视频放在同一事务中。分开导入可逐 P 在成功后发布；统一导入及组内拆分转换等待全部目标 P 就绪后一次发布，部分失败保留批次和正式缓存供重试。启动时重新检查待发布批次，纯缓存任务可补充当前批次身份。新确认的导入方式、直接保存或整组移除会使旧意图失效，并清理旧任务入库元数据；旧任务仍可完成缓存，但不得重建已移除分组或恢复旧组织方式。

下载仍写入 `filesDir/bilibili/{bvid}/{cid}.m4s`，先写 `.part`；已知响应长度必须与收到的字节一致，空文件不能成功，失败清掉本次暂存。有效正式文件和入库事务之间中断时，重试直接复用正式文件。完成事务包含曲目复用／新建、本地路径、下载关联和完成状态；入库失败回滚，不增加半完成曲目。

媒体地址被拒绝时沿用原来的重新解析重试，成功后继续补缓存视频字幕。下载管理、导出、删除音轨、字幕清理和临时缓存清理沿用现有规则；删除本地文件保留在线曲目。

## 字幕语言与翻译入口

字幕仍按原有中文优先规则自动选择，不提供字幕语言选择器。`BiliSubtitle.Ready` 同时携带所选字幕的可空 `language`；字幕加载结果将原文语言及是否可手动翻译传到播放器。字幕正文请求继续不携带登录凭证。

缓存仍为 `filesDir/bilibili/{bvid}/{cid}.json`，在保留 `body` 结构的同时，以应用专用 `_audioPlayerSubtitle.language` 字段保存语言。下载缓存和播放时补缓存共用写入逻辑；旧缓存没有字段时正常解析正文，不增加数据库迁移或强制联网。随音轨删除的字幕及其语言信息仍在同一个文件中。

所有来源（B 站、本地、asmr.one 及生成字幕）共用离线保守判断：明确的简体标识 `zh-CN`、`zh-Hans` 等直接确认；繁体或其他语言标识不判为简体。无标识或仅为 `zh` / `ai-zh` 时，正文去除显示标记后，须累计至少 20 个汉字、至少 3 种简体独有字，且没有繁体独有字、假名、韩文或其他语言字母才确认；只检查原文，不使用译文字段。简繁同形、短句及无法确定的内容保留翻译入口。

简体原文且没有译文时隐藏「生成翻译」，手动请求翻译的界面和任务入口同样校验。已有译文的显示切换、润色、运行中任务中止及听写后的自动翻译设置不变。切换曲目时清空上一首的判断状态。

特征字表由固定 OpenCC 1.1.9 的 `STCharacters.txt` / `TSCharacters.txt` 派生：只保留单码点键且其转换候选不含原字的项目，再排除两向键集合交集；按 Unicode 码点处理。结果随应用打包，无在线识别或模型依赖。来源、原字表 SHA-256 和许可见 `app/src/main/assets/licenses/OpenCC-NOTICE.txt`、`OpenCC-LICENSE.txt`。

## UP 主合集／系列与在线播放列表

### 接口与身份

`BiliCollectionKind.SEASON / SERIES` 区分合集和系列，身份为类型及远端编号；另保存 UP 主 UID、标题、封面、简介与视频数量，不使用 `folders.biliBvid`。

- `GET /x/polymer/web-space/seasons_series_list`：`mid`、`page_num`、`page_size=20`；合并 `items_lists.seasons_list` 和 `series_list`，按类型及编号去重，`page.total` 为合并目录数量。
- `GET /x/polymer/web-space/seasons_archives_list`：`mid`、`season_id`、`page_num`、`page_size=30`、`sort_reverse=false`；读取 `archives`、`meta` 与 `page.total`。
- `GET /x/series/archives`：`mid`、`series_id`、`pn`、`ps=30`、`sort=asc`；读取 `archives` 与 `page.total`。系列首批内容另读取 `/x/series/series?series_id=...` 的 `meta`，使标题和简介可随远端更新。

请求复用已有 WBI、匿名身份／登录及可取消的 HTTP 请求。访问限制、缺失字段和分页空转均作为错误，不当作空合集。视频目录保留接口顺序，时长字段按秒换算；分 P 按需通过现有 `videoDetails` 读取。

合集及系列统一使用首视频封面，忽略 `meta.cover`。UP 主目录卡片使用 `archives` 第一项的 `pic`；读取合集或系列内容时以第一页首视频的封面为准，后续页不覆盖，首视频变化后同步更新。`coverIsFallback` 保留为旧元数据的来源标记：仅保留已确认来自首视频的缓存，旧合集封面不再显示；已收藏列表和离线详情通过本地缓存的首视频重建封面。首视频没有封面地址时使用默认图标，不改用合集封面或其他视频，也不增加数据库列或版本。

### 收藏、缓存和刷新

播放列表入口统一展示自建列表与在线列表，`playlists` 保存公共头信息，`bili_collections` 保存一对一远端来源并对 `(kind, remoteId)` 建唯一索引，`bili_collection_videos` 保存 BV、位置、展示信息及已解析的分 P JSON。新表不引用曲目；不存凭证、临时媒体地址或完整接口正文。16→17 显式添加这两张表，原播放列表成员表保持曲目引用语义。

收藏在事务中复用已有远端身份，只创建列表及来源记录。已收藏列表打开后显示上次完整目录并读取全部分页；仅在分页全部成功且数量一致、请求仍有效时一次替换正式缓存，保留同 BV 的分 P 信息。条数与总数不一致或分页空转时自动重读一次；仍不一致则返回已读内容供界面展示并标注不完整，不写入正式缓存，已保存的完整目录保持不变。接口不提供失效条目清单，只能按条数判断完整度。来源记录的刷新版本阻止旧刷新覆盖新刷新；取消收藏后旧请求不能重建列表。失败、中止、重复空转或远端分页期间数量变化均保留旧完整目录。

本地收藏独立于账号保留。登录账号变化会取消旧查询和准备任务；扫码会话的同账号自动续期不清空本地收藏。在线列表不能改名、拖动改写目录顺序或增删单项；界面与仓储共同限制，自建列表选择弹窗排除在线列表。远端标题更新不改变用户收藏的排序时间。

### 播放与批量操作

`QueuePlayable.Saved / Remote` 与 `replaceAndPlayItems / appendItems` 支持已入库和未入库混排，持久化使用现有 `queue_items`。已入库项保留曲目编号，远端项保留 BV/CID 与稳定观看页；准备时优先读取有效本地副本。数据库队列修改使用事务，播放界面修改继续由 `PlayerClient` 队列互斥协调。

合集详情提供正序、倒序、随机三种本地排序，正序以接口目录顺序为准。ViewModel 分别保存远端原序目录和展示顺序；排序仅影响当前页面及随后发起的播放、追加、保存、下载和复制操作，不写入目录缓存、不重排当前队列。随机按本次随机种子与 BV 生成稳定位置，分页和刷新不改变已有视频的随机相对顺序，再次选择随机时生成新种子。切换排序保留所选 BV；多选操作按展示顺序处理所选项。封面始终基于远端原序首视频。

点单视频沿用单 P 直接播放／多 P 单选行为；整合集操作先准备完整目录，再按当前展示的视频顺序和 P 序号展开，不反转或打乱视频内部的 P。多选时隐藏顶部「按当前排序播放全部」「加入播放队列」，取消全部选择后恢复，使用多选栏播放或追加所选项。准备阶段不改变当前队列，不创建曲目或播放列表；部分视频失败须由用户选择重试或继续成功项。整合集自动续页播放及后台追更不在本版范围。

保存和下载共用 `BiliImportRequests` 及 `enqueueBiliImports`，继续使用根目录、既有组织方式转换确认和下载批次发布规则。复制到自建播放列表时先输入名称并选择入库方式，按视频独立入库；仅将成功请求中实际选择的 BV/CID 组成新列表，在一个事务中发布列表和成员，避免把未勾选的已有 P 带入。失败项目单独反馈，不创建空列表；已经成功入库的内容保留。

有缓存分 P 元数据和有效本地音频时可以离线准备。单视频允许只提供已有本地副本的 P；整视频批量操作要求目标 P 均可读取。没有必要信息或本地文件时明确失败，不以目录视频信息伪造音轨身份。

取消收藏只删除列表、来源及目录缓存；不会连带删除曲目、音频、字幕或当前队列。刷新目录同样不会改变当前队列或清理已落盘内容。B站账号订阅不属于本地收藏功能。
