# B 站搜索、播放和下载

本文依据 2026-11-01 Android 当前实现。入口是「在线搜索 → B站」，音频库「导入 → 导入在线音频」切换到在线搜索并恢复原页面状态；不传入原文件夹，保存的内容放音频库根目录。

## 搜索和输入

「视频 / UP主」各自保留输入和结果；「作品 / B站 / YouTube」分别保留输入、结果和滚动位置。UP 主投稿在搜索页内展开，按返回先退出选择或投稿列表，原搜索位置保留。

`BiliSearchInput` 先识别 BV 号（也支持链接／分享文字中的 BV），再识别 `space.bilibili.com/{uid}` 主页链接或 `UID:数字`。纯数字仅在 UP 主模式作为 UID，视频模式仍按关键词搜索。昵称只在 UP 主模式搜索；主页链接校验真实主机名，不接受相似域名。

现有 `BilibiliClient` 新增：

- `searchVideos(keyword, page)`：返回 `BiliPage<BiliVideoHit>`，包含 BV、标题、作者、封面、时长和作者 UID。
- `searchUploaders(keyword, page)`：返回 `BiliPage<BiliUploader>`，包含 UID、昵称、头像、简介、粉丝数和投稿数。
- `uploaderVideos(mid, page)`：返回该 UP 主最新投稿的视频页。UID 直达时标题使用 UID；未取得资料不伪造昵称、头像和粉丝数。
- `videoDetails(input)`：复用 `/x/web-interface/view`，返回视频本身的标题、封面和分 P，供剪贴板导入预览；原标题不混入第一 P 的名称。
- 原有 `lookup(input)` 继续返回 `List<BiliPart>`，包含每个分 P 的 BV、CID、页码、标题、作者、时长和封面，供播放、保存及下载使用。

从剪贴板识别到 BV 时，应用先显示视频标题和封面；确认前不入库。多 P 在同一弹窗勾选，默认全选，确认后复用 `importParts` 保存根目录。所有分 P 已保存时显示「已在音频库」。

## 请求与分页

请求复用已有 B 站登录、匿名 buvid／ticket 和 WBI 签名，不增加登录方式或外部搜索服务。搜索解析使用 Kotlin 序列化，不依赖 Android 的 `org.json`。标题去除搜索高亮 HTML 标签，封面统一为 HTTPS，时长转为毫秒。

- `GET https://api.bilibili.com/x/web-interface/wbi/search/type`：`search_type=video` 或 `bili_user`、`keyword`、`page`、`page_size=20`。视频使用默认综合排序 `order=totalrank`，用户使用 `order=0`。
- `GET https://api.bilibili.com/x/space/wbi/arc/search`：`mid`、`pn`、`ps=30`、`order=pubdate`，从 `data.list.vlist` 读取投稿，按 `data.page.count` 判断后续页。
- 以上参数经 `WbiSigner` 添加 `wts` 和 `w_rid`。错误码 `-403` 刷新 WBI 密钥后最多重试一次，其余错误不自动重复搜索。Referer 使用搜索页或指定 UP 主主页。
- `GET https://api.bilibili.com/x/web-interface/view?bvid=...`：读取分 P。搜索、投稿和分 P 浏览的主体请求都可随协程取消关闭 HTTP。

滚动加载时按 BV／UID 去重，重复页没有新项目时停止自动读取；失败保留已有项目与下一页编号，重试仍请求同一页。新查询、切换视频／UP 主模式、打开其他 UP 主时取消旧请求，并检查请求编号，防止迟到响应覆盖新结果。中止后暂停自动分页，手动「加载更多」才继续。

接口需要登录、访问受限、网络异常与空列表分别处理。HTTP 412、API `-412` / `-352` 等显示访问限制；不把 HTML 错误页或缺少列表的数据当成“没有投稿”。不记录 Cookie、请求头、完整媒体地址或接口正文。

## 视频和分 P 操作

点视频只播放这一首：单 P 直接播放，多 P 弹窗单选；不会保存曲目或把整页结果放入队列。保存／下载多 P 时默认全选，可以逐段取消。长按支持视频多选、全选、批量保存和下载；先汇总读取所选视频的分 P，再在按视频分组的清单中确认。读取失败的项目单独展示，其余项目仍能执行。

已保存内容使用原曲目。未保存内容使用远端队列，`source=BILIBILI`、`workno=bvid`、`fileKey=cid`、`remoteUrl` 保存稳定观看页地址或已有本地缓存路径；转成媒体条目时按 BV/CID 生成 B 站 DASH 音轨清单，不把观看页交给音频解码器，不保存临时 CDN 地址。已有缓存优先本地播放，字幕仍按 BV/CID 查找。

保存调用现有 `importParts`，以 BV/CID 复用曲目，原编号、文件夹和字幕关联保留。显示已保存、已下载和正在下载的分 P 数量，不根据部分分 P 推断整部视频已处理完。

## 下载成功后入库

`DownloadCenter.enqueueBili(parts, autoImport = false)` 保持原默认行为：收藏夹缓存不自动入库。搜索页使用 `autoImport=true`；排队时只保存下载任务，成功才保存曲目。

数据库版本为 14：13→14 仅执行 `ALTER TABLE downloads ADD COLUMN biliImportPart TEXT`，可空列没有 DEFAULT。非空值是待入库 `BiliPart` 的 JSON，包含稳定视频身份与展示信息，不包含临时媒体地址或登录信息。旧记录为 null，行为不变。

`BiliDownloads` 在事务中按 BV/CID 去重。同一分 P 已有排队／运行任务时补充入库元数据，不新建任务；工作者完成时重新读取元数据。已有完整缓存时直接保存并关联完成记录；失败重试仍保留入库意图。用户识别挂上的本地文件也不会额外下载。

下载仍写入 `filesDir/bilibili/{bvid}/{cid}.m4s`，先写 `.part`；已知响应长度必须与收到的字节一致，空文件不能成功，失败清掉本次暂存。有效正式文件和入库事务之间中断时，重试直接复用正式文件。完成事务包含曲目复用／新建、本地路径、下载关联和完成状态；入库失败回滚，不增加半完成曲目。

媒体地址被拒绝时沿用原来的重新解析重试，成功后继续补缓存视频字幕。下载管理、导出、删除音轨、字幕清理和临时缓存清理沿用现有规则；删除本地文件保留在线曲目。

## 验证记录与待验收项

2026-11-01 主机通过官方接口只读探测：匿名视频关键词搜索与 UP 主昵称搜索成功，各返回 20 条；UP 主投稿接口返回 HTTP 412，因此没有在本机验证真实投稿列表成功。该结果仅代表这次网络出口，不能推断所有手机或账号都会失败。

Kotlin 编译、Debug APK 与设备测试 APK 构建通过，125 项定向单元测试全部通过。主机 SQLite 对照 Room 生成的新装 SQL 验证了 13→14 升级：10 张业务表的结构、索引、外键和旧行均保留，新增列可空且没有默认值。

定向单元测试覆盖输入优先级、昵称／UID 分流、JSON 解析、去重、分页错误重试、WBI 密钥重试、访问受限、取消、旧响应隔离、入库元数据和分 P 选择。设备测试代码覆盖 13→14 与新装结构、旧数据关联、任务去重、旧任务追加入库意图、成功复用曲目／文件、失败不入库及远端队列媒体身份；12→13 的既有设备测试也追加 13→14 升级链。

本轮不自动安装手机。设备测试及真实投稿成功、在线播放／后台播放、分 P 弹窗、跨来源和投稿返回位置、缓存删除后在线播放等交互验收，仍需在设备上执行；编译成功不等于这些设备行为已经验证。
