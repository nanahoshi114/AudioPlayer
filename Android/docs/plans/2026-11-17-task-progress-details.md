# 下载与字幕任务详细进度实施计划

## 一、目标与范围

统一增强音频下载、DLsite 整包、音频上传、在线与本机听写、翻译和润色的进度展示，让用户能够判断任务正在等待、传输、处理还是保存。

已确认的展示方式：

- 任务行直接显示阶段、进度和常用统计，提供独立的详情展开按钮。
- 完成或失败后保留本次尝试的摘要，不保存每秒数据和完整事件时间线。
- 后台通知同步阶段和速率，数值最多每秒刷新一次。
- 保持现有并发数量、请求顺序、重试次数、超时、中止及恢复行为。

范围排除：听写模型下载（`OfflineModelDownloadService` / `OfflineWhisperModelManager`）与外部打开暂存下载（`ExternalFileSession`）已有各自的进度展示，本次不改动、不接入统一组件。

## 二、各类任务展示内容

### 音频下载与整包

- 普通下载显示：等待资源、解析地址、请求中、等待响应、下载中、检查与保存、关联曲目。仅在相应操作真实发生时切换阶段。
- 下载中显示已接收量、已知总大小、百分比、速率、运行耗时和预计剩余时间。排队时区分等待下载名额与等待同作品整包处理（原因来源见第三节）。
- 上报现有地址刷新、分段重试和续传事件，显示当前重试次数；不因此新增重试行为。重试次数指**本次尝试内部**的重试（地址刷新、分段重试、续传、翻译调优）；用户点重试开启新尝试并重新计数。
- 普通下载（asmr / DLsite Play / B 站）地址刷新后删除半成品从头重下，**没有断点续传**；"续传"仅适用于 DLsite 整包暂存和 YouTube 已完成分段。
- 复用本地副本直接完成的任务（整包已解压复用、YouTube 缓存命中、B 站音轨已存在）明确展示"复用本地文件"，不显示 0 B / 0 s 的虚假统计；整包复用路径现有 `finish(0, 0)` 清零字节的行为保留，摘要以复用结果为准。
- DLsite 整包增加当前卷序号、本卷信息、累计下载量、解压文件数及大小、整理条目进度、冲突跳过数量。总卷数或总大小未知时只展示已知信息，不提前解析后续分卷来获取总量。
- 整包下载期间总量恒未知（逐卷解析、全部完成才确认总量），**不展示整体百分比和整体 ETA**；响应头提供每卷大小时展示当前卷百分比与当前卷 ETA，否则保持未知；附累计已下载字节。
- B 站音轨完成后单独展示附带字幕状态，区分获取中、已保存、无字幕、需要登录和稍后重试，保留音轨已经完成的事实。状态映射：`Ready` 且写盘成功→已保存；`Missing`→无字幕；`NeedsLogin`→需要登录；异常、超时或写盘失败保留待补标记→稍后重试（同一次后台运行每条任务只尝试一次）。字幕抓取是 DONE 下载行上的附属子任务，使用独立子任务键（见第三节），不覆盖音轨下载的摘要。

### 听写

- 千问在线听写显示：获取上传凭证、上传音频、提交任务、服务端排队、服务端听写中、获取结果、保存字幕。上传阶段增加字节数、百分比和速率。
- 将服务端 `PENDING`、`RUNNING` 分别展示为排队和听写中；`UNKNOWN` 显示"服务端状态暂不可确认"。继续沿用原有轮询（2 秒间隔）和超时（30 分钟）规则，不展示接口未提供的识别百分比、排队名次或完成时间。
- 进程重启后恢复远端任务（`remoteJobId` 非空）时**跳过上传**，直接进入查询恢复阶段，展示"恢复远端任务"，随后按真实响应切换排队或处理中；这不是新尝试，内存统计从零开始，耗时只计本进程运行段。手动重试会清空远端任务编号，属于新尝试、重新上传。
- 自部署 Qwen3-ASR 显示读取模型信息、上传音频、等待听写结果、保存字幕。上传完成后无法确认服务器内部进度，保持不确定进度展示；等待结果不属于传输阶段，不适用"等待数据"判定。
- 本机模型显示加载模型、听写中和保存字幕；详情展示解码、人声检测或片段识别等当前子阶段。进度使用实际处理的音频时间，补充平均处理倍速和估算剩余时间。
- **处理音频时间口径**：按输入音频时间轴位置计算，包含 VAD 跳过的静音，不是识别段时长之和（求和会永远到不了 100%）。SenseVoice 在纯 VAD 消费期间也要推进处理时间，不能只在切分段产出时回调；Parakeet 按输入块推进一次，双声道不翻倍。总时长未知或为 0（曲目时长缺失且 MediaMetadataRetriever 失败）时退回不确定进度，不产生虚假百分比。
- 等待前置下载时绑定原下载任务显示其阶段和进度；旧任务依赖字段为空时沿用 `relatedDownload` 兼容推断，推断目标已终态或不确定时只显示"等待音频下载"，不强行绑定。复用本地音频、已有字幕或远端任务时明确展示复用结果；`rememberDone` 等从未执行的合成完成记录不生成摘要。

### 翻译与润色

- 显示等待执行、翻译中、修正结果、润色中和保存译文。等待执行覆盖 `TranslationExecution` 全局串行锁的排队等待（自动翻译、独立翻译和润色共用一个执行位置）。
- 增加当前批次、总批次、已处理输入字幕条数、当前批次等待时间和总运行耗时。批次等待时间从本批第一次请求起算，含日文路径每批最多 2 次请求。
- 每批结果通过校验后更新计数；按输入字幕条数计算，避免字幕合并造成进度失真（日文校对输出条数 ≤ 输入条数）。结构损坏盲目重试和定向调优的第二次请求不增加计数，交付才计。
- 翻译与润色是不同阶段，批次计数器按阶段重置：翻译按全部输入条数分批（日文 20 / 普通 40），润色只对有译文的条目按 40 分批，总批次数不同。
- 翻译行没有字节传输，速率恒显示"—"，以批次统计代替。
- 保留"原文已生成但翻译失败""自动润色失败，已保留初译"等结果，不将部分批次完成视为整个任务完成。自动润色失败在摘要中记为"润色失败已保留初译"标记，不算任务失败。

## 三、统一进度采集与统计

新增应用级进度组件（AppGraph 进程级单例，服务经 `graph()` 取同一实例），由下载、听写、翻译及通知共享。

### 任务键与尝试标识

- 任务键为"**任务类型＋任务编号＋子任务**"。类型区分下载、听写和独立翻译；B 站附带字幕使用下载编号＋`BILI_SUBTITLE` 子任务键，与音轨下载隔离。自动翻译继续归属于原听写任务键。
- 三类任务的重试都复用原行 id（`requeue` / `requeueWithFile` / `requeue` 均为 UPDATE），因此**尝试标识在每次执行开始时于内存生成**，不依赖行 id。回调携带尝试标识和阶段标识，组件拒绝旧尝试或旧阶段的覆盖。
- 尝试标识检查是现有 DB 判活守卫（`stillActive` / `isActive`）的**补充而非替代**：取消路径先写 DB 终态再 cancel runner，保留原判活语义，避免弱化取消。
- 进程重启恢复（听写 RUNNING 行续轮询、整包暂存续传）不是新尝试；内存统计丢失后从零开始，不补算应用未运行期间的耗时。

### 阶段、回调与统计

- 提供统一的阶段、字节、处理单元、重试和结果回调。实时统计保存在内存中，阶段变化立即发布；数值统一每秒采样。无**排队或运行中**任务时停止计时器，耗时使用单调时钟计算。
- 现有回调整改：本机听写回调由单一 Float 改为携带（已处理音频毫秒、总音频毫秒、子阶段）；翻译回调增加（阶段、批次序号、总批次、已处理输入条数）；千问轮询增加服务端状态回调；解压、整理增加计数回调。所有采集均复用现有读写过程，不新增探测请求。
- 整包 `downloadPart` 的进度回调每次 read 都触发、无节流，1 秒采样必须在组件侧完成，不依赖回调频率。
- 保留现有 DB 进度写入不变：下载每 256 KiB 节流写 `activeProgress`（RUNNING 守卫），听写回调写 `setProgress`。这些写入是进程中断后字节信息的兜底；内存组件只叠加阶段、速率、ETA 等实时数字，**不新增逐秒写库**。阶段与终态另外保存一次摘要检查点（见第四节），不跟随每秒采样写入。

### 速率与 ETA 规则

- 速率采用最近 **5 秒**的实际传输字节平均值，按秒采样滑动窗口计算。冷启动不足 5 秒时按已有样本平均（至少 1 秒数据），否则显示"—"，避免小文件全程无速率。
- **窗口复位**：阶段切换、地址刷新从头重下、新尝试开始时清零或隔离速率窗，防止旧窗口字节造成虚假高速率。
- **分段回滚**：YouTube 段重试截断本段、累计字节回跳；速率按秒采样取正增量（或维护"已完成段＋本段最大偏移"的单调接受字节数），不产生负速率。
- **续传**：整包续传初始 offset 为暂存文件长度，已有文件不计入本次传输量和速率；服务器忽略 Range 返回 200 整体重写时，重写字节是真实传输，计入本次统计。
- 排队、解析地址、等待识别结果和翻译处理时速率显示"—"。传输阶段连续 5 秒没有新数据时显示等待数据及等待时长，不自动判定失败；该判定只适用于传输阶段，不适用于服务端处理、本机推理和翻译等待。
- 只有总量已知且速率有效时才展示预计剩余时间；估算仅对应当前阶段或当前分卷，不估算云端听写的剩余时间。本机听写 ETA ＝（总时长－已处理时长）/ 平均处理倍速。

### 上传统计

- 现状没有任何计数 sink，Qwen OSS 表单与 Qwen3 multipart 均为裸 `file.asRequestBody`；新增计数 RequestBody 包裹文件部分。
- 上传统计**文件内容的发送量**，不含 multipart 边界开销；上传达到 100% 后进入等待响应阶段（写完 sink ≠ 服务端收完）。
- OkHttp 重定向或重试会再次调用 `writeTo`，计数必须按请求复位（EventListener 关联或每次尝试新建计数 body）。网络请求事件按请求独立关联，支持并发、重定向和重试；可参考 YouTube 现有 diagnostics 事件模式扩展。

### 排队原因与批量终态对账

- 排队等待原因来自调度判断：将 `canStartDownload` 重构为返回密封原因（可开始 / 等待名额 / 等待同作品整包），Boolean 由原因导出，调度行为不变；展示与调度共用同一规则，用 `TaskPumpTest` 现有用例保证一致。不在组件里另写一套判断逻辑。
- 多条批量终态路径不经过单任务回调：`failQueue`（`failActive` / `failActiveTranslations`）、`stopJobs` / `failAfterServiceStop`、启动中断登记、`SubtitleTaskService.onTimeout`。组件必须对这些路径对账收尾（observe 同一 DB 状态流，或在调用点显式 finalize），否则内存状态泄漏、计时器不停、摘要缺失。
- 启动对账在 `subtitleRecovery`（字幕发布恢复）完成之后进行，再登记中断翻译的摘要，避免先写"失败"摘要、随后发布恢复成功造成矛盾。下载启动中断登记独立于字幕恢复，两处顺序都要覆盖。

## 四、页面、通知与摘要保存

### 页面与通知

- 任务行保留标题、阶段标签和进度条，增加量、速率、耗时或批次统计；窄屏允许换行，不截断关键数值。trailing 区已有中止 / 重试 / 删除按钮，详情按钮加入后验证窄屏布局。
- 独立的"任务详情"按钮展开统计、等待原因、重试情况、本次模型或平台、失败阶段和结果摘要，不改变已完成音频点击播放的行为（DONE＋非整包＋localPath 的整行点击保留）。
- 展开状态按任务键用 `rememberSaveable` 保存（至少保留旋转），保留分类切换和滚动位置的现有行为。重试复用同一任务键，展开状态自然保留；B 站字幕子任务键独立。
- 翻译行在字幕加载完成前总条数未知，保持不确定进度；加载完成后按输入条数展示确定进度。
- 音频分类顶部与通知显示运行数、排队数和总速率（总速率＝各传输阶段任务速率之和，排队任务不计入）。并发多任务时通知内容规则：总速率＋运行 / 排队数＋第一个运行中任务的阶段与标题。字幕通知可同时显示听写、翻译阶段。
- 页面和通知读取同一进度数据：DB 状态流＋内存数值流 combine。阶段立即更新，数值最多每秒更新一次，并跳过内容未变化的通知。`AudioDownloadService` 现状每次 DB 发射都 notify、无去重无节流，需引入显式 1 秒 ticker＋内容去重（参考 `OfflineModelDownloadService` 现有 1 秒轮询模式）；`SubtitleTaskService` 已有内容去重，补 ticker 即可。
- 详情不展示密钥、Cookie、上传凭证（policy / Signature）或完整临时媒体地址。摘要错误文本复用现有脱敏规则（过滤含 `://` 的消息），失败阶段存阶段枚举名而非原始异常文本。

### 历史摘要与兼容

- 新增类型化的 `TaskProgressSummary`，使用 **kotlinx.serialization**（已有依赖与 `bili_collections.metadata` 先例）序列化，不用 org.json（单测禁止依赖 Android org.json）。
- 摘要为**分段结构**，解决同行多阶段覆盖问题：
  - 下载行：下载段＋可选 B 站附带字幕段；字幕抓取终态只写字幕段，不覆盖下载段。
  - 听写行：听写段＋翻译段＋润色标记。听写终态写听写段；自动翻译终态**合并**翻译段，不抹掉听写段的耗时与模型统计；翻译失败重试只覆盖翻译段。
  - 独立翻译行：单段。
- 每段保存最近一次尝试的耗时、传输量及传输耗时、模型或平台、处理数量（音频毫秒 / 字幕条数 / 解压文件数）、内部重试次数、结果与失败阶段；平均速率由摘要计算，传输耗时 ≤ 0 时一律显示"—"，防除零。
- 结果枚举包含：完成、失败、已中止、中断、复用、恢复远端任务。复用完成写复用结果、不伪造统计；从未执行的合成完成记录摘要保持 NULL。
- 在下载（downloads）、听写（whisper_jobs）和独立翻译（translation_jobs）三张任务表分别增加可空的 `progressSummary` 文本列。
- 数据库升级为 **20**，提供显式 19→20 迁移。新增列不设置数据库默认值或实体默认值注解，旧记录保持 NULL。
- 三处 requeue DAO（`downloads.requeue`、`whisper.requeueWithFile` / `requeueForDownload`、`translations.requeue`）在现有清零基础上**同步清空 progressSummary**，新尝试排队期间不显示上一次失败的摘要。
- 阶段转换和终态保存摘要，实时数字不逐条写库；现有字节进度写入频率不变；阶段转换和终态另外保存一次摘要检查点，原先没有写库操作的阶段会新增一次事件写入，不新增逐秒写库。批量终态路径（第三节对账）同样落摘要；进程中断后内存统计缺失时只登记结果与失败阶段，数值保持 NULL。重试覆盖为新尝试的摘要，不保留完整尝试历史。
- 字幕发布恢复优先于进度恢复，终态摘要与已有任务发布结果保持一致。进程中断后不补算应用未运行期间的耗时；缺少历史统计时显示"—"。
- 旧记录继续显示已有状态和字节信息，不根据文件修改时间推算历史耗时或速率。

## 五、实施顺序与验收

按以下顺序实施：

1. 统一进度类型（**含任务键结构与摘要分段结构**）和统计组件；
2. 数据库迁移与摘要（含 requeue 清摘要的 DAO 修改）；
3. 各执行链路回调（含 `canStartDownload` 原因重构、批量终态对账、发布恢复顺序）；
4. 列表和通知；
5. 回归测试。

保留当前工作区已有并行下载改动，同步更新 README、相关接口文档（whisper / dlsite / bilibili）和数据库版本说明（**含 AGENTS.md 的"当前版本为 19"改为 20**）。

重点验证：

- 并发任务的进度、速率及计时互不串用；总速率正确，数值刷新不超过每秒一次。
- 小文件、未知长度、低速、无新数据、分段重试、断点续传和地址刷新时，进度及速率含义正确；速率窗复位、冷启动平均、段回滚非负、续传 offset 排除与 200 整体重写计入各有用例。
- 中止、重试、切换阶段后，旧回调无法覆盖新状态；批量终态（failQueue、服务停止、启动中断、onTimeout）后内存收尾、计时器停止、摘要落库；最终完成仍以现有发布及清理流程为准。
