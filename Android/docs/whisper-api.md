# 听写接口说明

播放器支持线上听写、自部署听写服务和两种本机离线模型。

## 听写模型

在「设置 → 听写和翻译」里选择。每个模型分别保存地址和口令（本机模型无需地址和口令）。切换模型或翻译平台时会载入该项保存过的字段，点「保存」后才启用所选项。「清除」移除当前选中项的地址、口令或翻译模型名，当前启用的模型或平台保持选定。进行中的任务继续用它自己的模型和口令。

| 界面上的名字 | 地址 | 请求 | 说明 |
| --- | --- | --- | --- |
| `qwen-audio-3.1-asr` | 固定 `https://dashscope.aliyuncs.com`，界面不显示 | 阿里云官方接口 | 只填 API Key。不论时长都先上传到临时存储再轮询，模型名 `qwen-audio-3.1-asr-flash-filetrans`。超过 1GB 不上传。语言提示为日语 |
| `Qwen3-ASR` | 用户填写，不能为空 | `GET {地址}/v1/models`，再 `POST {地址}/v1/audio/transcriptions` | 先读取服务上的模型名，取名字里带 `qwen3-asr` 的第一项；没有就取列表第一项；服务没有列出模型时用 `Qwen/Qwen3-ASR-1.7B`。语言日语，`response_format` 为 `json`。返回分段时间就按段写字幕；只有整段文字时写成覆盖整首时长的一条；没有时长也没有分段时间时记为「没有分段时间」 |
| `SenseVoiceSmall` | 本机运行 | 离线识别 | 使用 2024-07-17 多语种包，识别语言设为日语 |
| Parakeet 0.6B 日语（CTC） | 本机运行 | 离线识别 | 使用 NVIDIA 日语模型的 INT8 CTC 导出版本 |

`qwen-audio-3.1-asr` 是线上模型：界面不显示地址，只保存 API Key，不使用地址栏里留下的内容。`Qwen3-ASR` 要填地址和口令；服务不检查口令时，填任意非空内容即可。保存听写地址时不会自动补 `/v1`；`Qwen3-ASR` 只在请求时补。

`qwen-audio-3.1-asr` 上传后的轮询每 2 秒一次，总上限 30 分钟。听写任务串行执行，服务端长期不给结果时不能让一个任务永久占住队列：超时先取消正在查询任务状态的网络请求，再把任务记为失败「听写超时，请重试」，可以手动重试。超时只针对轮询，用户点「中止」仍然是取消，任务显示「已中止」，两者不混淆。

地址是局域网、本机或 `.local` 时（只可能是 `Qwen3-ASR`），Android 17 要在请求前申请 `ACCESS_LOCAL_NETWORK`。公网地址不申请。判定使用 `isLocalNetworkAddress`，仅解析字面 IP、不额外发起 DNS 查询。已移除模型的偏好迁移至 `qwen-audio-3.1-asr`（不生成虚假密钥，旧模型待执行任务明确失败）。`filesDir/whisper-src/` 暂存文件保持无后缀，上传按文件头设置格式，任务结束/取消/重试后仅清理无任务引用暂存（重试优先复用原文件，其次从曲目本地文件复制）；本机模型直接读取本地文件，且 JNI 解码与 `release` 不得并发。

## 字幕后台任务

听写和自动翻译使用独立执行通道：同时听写一首，原文保存成功后将 `whisper_jobs.translateStatus` 置为 `QUEUED`，释放听写位置并继续下一首。自动翻译、独立翻译和润色共用一个执行位置，等待期间保持排队，取得位置后才标为 `RUNNING`。原听写任务行显示「等待翻译」或「翻译中」，相同生成字幕指纹的翻译请求统一去重。翻译或润色失败不阻塞其他音频的听写。字幕写入仍受写锁、源字幕校验和持久化发布记录保护，网络请求不持有字幕写锁。

用户发起听写、翻译或润色时，应用启动同一个 `dataSync` 前台服务。该服务覆盖本机推理、在线上传和结果轮询、翻译及润色。需要先下载音频时，字幕服务等待音频下载服务完成，文件就绪后继续听写。确认前置下载时同时申请两个服务。下载任务绑定已入库目标，未入库曲目可在已有本地副本时直接听写。听写结束后需要自动翻译时，字幕服务继续运行到翻译和润色结束。任务期间持有部分唤醒锁，全部结束后释放并移除通知。点击通知可进入「下载与任务 → 字幕任务」。

中止一项字幕任务会取消这项任务的网络请求，本机听写在当前片段推理结束后停止。等待音频时中止听写，音频下载仍会继续。系统终止进程后，重新打开时接手仍排队或正在听写的任务。阿里云已提交的任务先按保存的远端编号和时间继续查询。已超过 30 分钟时，最多做一次 15 秒的查询以取回已完成结果。Android 15 及以上会对应用的 `dataSync` 服务合计计时，字幕、音频和模型下载共用额度。达到系统时限时字幕服务会结束，并将未完成的任务标为超时。 [Android 前台服务时限](https://developer.android.com/develop/background-work/services/fgs/timeout)

对已有字幕单独发起翻译、复用听写结果后仅翻译，以及手动润色，分别在读取源字幕前登记可查看和重试的任务。发布译文时先记录待写入内容，再替换文件并完成任务。下次启动先恢复已记录的发布，再把已经开工但中断的自动翻译，以及中断的独立翻译和手动润色标为失败；尚未开工的自动翻译保留 `QUEUED`，重新进入前台后接手。服务超时或销毁时，当前服务持有的排队和运行任务登记失败，原文和已发布译文保留。`QUEUED` 复用现有字符串状态列。

### 自动翻译失败后的重试

听写完成但自动翻译失败时，任务保留为 `DONE + translateStatus = FAILED`，可直接在「下载与任务 → 字幕任务」点「重试翻译」，不必重新听写。重试与手动发起翻译共用 `TranslateCenter` 的提交锁：同时需要生成字幕写入锁和提交锁时，固定先取得 `generatedWriteLock`，再取得 `submissions`，避免两个入口在锁顺序上互相等待。

重试在事务内重新核对任务仍为 `DONE + FAILED`、翻译配置有效、源字幕文件可读且与任务记录的模型、地址和指纹一致，并确认字幕尚未翻译。若同一字幕已有进行中的自动翻译或独立翻译（`hasActiveGenerated`），返回「已有翻译任务在运行」而不是重复入队；已存在持久化发布记录的任务也不能再次提交。重试只清除摘要中 `TRANSLATION` 分段，保留听写段的进度、耗时和结果，并把 `createdAt` 更新为当前时间；新一次尝试从重置后的翻译进度开始统计，任务在字幕列表中移到较新的位置。

### 任务时间与隐藏

`whisper_jobs.createdAt` 和 `translation_jobs.createdAt` 记录任务创建或最近一次重试排队的时刻。字幕任务列表把听写、独立翻译和手动润色按 `createdAt` 从新到旧混排，时间相同时再按编号排序。重试听写、重试翻译和重新入队都会刷新 `createdAt`，因此重试后的任务排到前面。

`dismissedAt` 只用于从任务列表隐藏已结束的记录，不删除数据库行和生成字幕文件。`observeVisible()` 过滤已隐藏的行，但按指纹查找任务的 `forFingerprint()` 仍会看到它们。因此同一音频再次请求生成字幕时，仍能按内容、模型和地址命中已隐藏的完成记录并复用原有字幕，不会重复生成。删除失败任务、隐藏完成记录和重试都要避开仍被 `subtitle_publications` 引用的任务；发布中的任务不能隐藏或删除。

## 本机模型

在「设置 → 听写和翻译」选择模型，点「下载模型」并选择 GitHub 或 Hugging Face。每次下载和重试默认选中 GitHub。安装后点「保存」启用。

- **SenseVoiceSmall** 使用 `2024-07-17` 多语种 INT8 版本。GitHub 下载约 155 MiB，Hugging Face 下载及安装占用约 229 MiB。文件位于 `filesDir/sense-voice/`，已有安装继续有效。 [GitHub 发布包](https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17.tar.bz2) · [Hugging Face 固定版本](https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/tree/2365baeacb507f821a0c8120fcee3d484dba7a07)
- **Parakeet 0.6B 日语（CTC）** 使用 `sherpa-onnx-nemo-parakeet-tdt_ctc-0.6b-ja-35000-int8`。GitHub 下载约 467 MiB，Hugging Face 下载及安装占用约 625 MiB。文件位于 `filesDir/parakeet-tdt-ctc-0.6b-ja/`。 [GitHub 发布包](https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-nemo-parakeet-tdt_ctc-0.6b-ja-35000-int8.tar.bz2) · [Hugging Face 固定版本](https://huggingface.co/csukuangfj/sherpa-onnx-nemo-parakeet-tdt_ctc-0.6b-ja-35000-int8/commit/bef18eb066808c90bd0f5df5be685767b0732de8)
- **下载和删除**。GitHub 归档边下边解，Hugging Face 逐个下载 `model.int8.onnx` 和 `tokens.txt`。校验完整性后发布模型目录。下载可取消，重试从头下载。删除前需确认，对应模型有排队任务或仍在推理时需先中止并等待当前片段结束。
- **后台下载**。用户确认来源后启动 `dataSync` 前台服务，覆盖下载、校验和安装。切换页面、按 Home 或熄屏时可继续。设置页和通知共享进度，均可取消对应模型。通知权限被拒绝时仍可在设置页操作。所有任务结束后服务退出。进程被强制停止后需手动重试。
- **推理与分段**。两个模型都用 sherpa-onnx 在 arm64 设备的 CPU 上推理。MediaExtractor 和 MediaCodec 将音频逐块解码并重采样为 16 kHz，送入识别器的单声道片段最多 28 秒。Parakeet 以 512 个采样点为单位读取 Silero 人声概率，检测状态随音频连续推进。双声道分别检测并取较高概率，约 250 毫秒确认起声，500 毫秒静音结束语音。识别前以核心语音范围判断声道，相关度达到 0.65 时平均混合，否则使用能量较高的一侧。中止在当前片段推理结束后生效。
- **Parakeet 音频交界**。自然语音段两端最多保留 200 毫秒上下文。核心段上限 26 秒，切分时回看 4 秒，优先在最长的短静音中点切开，其次选连续三个窗口的平均人声概率最低且不超过 0.35 的位置。缺少候选时，切点两侧各额外保留最多 800 毫秒供相邻识别段使用。拼接时按文字和时间匹配重叠内容，各保留一份。匹配不明确时按切点分配文字。重叠段时间戳无效或文字片段拼不回识别全文时，只重识别该段的核心范围。仍无法取得可靠时间时保留识别全文及核心起止时间。
- **Parakeet 字幕**。词片段时间换算到整首音轨后再组织字幕，允许一条字幕跨识别段。句末标点或至少 480 毫秒的空隙触发换条。超过 6 秒或 40 个非空白字符时，往回 1.5 秒优先选择最近的逗号、顿号或分号，其次选至少 240 毫秒的空隙。回退后前一条至少 1 秒且 6 个非空白字符。没有合适的断点时继续保留当前句子。原文标点随字幕保留。
- **字幕复用**。本机任务的 `endpoint` 为空。生成文件按音频指纹存放，并记录生成模型和地址。重新请求时按文件中的信息判断是否复用，旧文件沿用已完成任务记录。翻译保留生成信息，自动翻译仍使用配置的在线平台。用户在播放页选择「重新生成」时，任务保存 `forceRegenerate = true`，即使内容、模型和地址相同也跳过复用并重新听写。

Parakeet 由 NVIDIA 创建，sherpa-onnx 将其 CTC 分支导出为 ONNX 并量化为 INT8。模型采用 CC BY 4.0 许可。 [NVIDIA 原始模型及许可](https://huggingface.co/nvidia/parakeet-tdt_ctc-0.6b-ja#licence) · [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) · [sherpa-onnx 导出说明](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-ctc/nemo/japanese.html)

## 日文字幕校对与翻译

翻译平台限定千问 AI 平台和 DeepSeek，地址固定、密钥与模型名按平台独立保存；平台地址、默认模型及思考参数集中于 `data/TranslatePlatforms.kt`（修改时保留平台字段差异），思考内容 `reasoning_content` 不写入字幕。

生成字幕后的自动翻译和对现有字幕发起的翻译共用处理流程。「设置 → 听写和翻译 → 翻译行为选项」提供独立的「日文校对」和「语义合并」开关（默认均关闭，仅对日文字幕生效）：

- **两者均关闭（默认）**或明确为其他语言：使用逐条行协议，每批最多 40 条，不校对原文、不合并条目。
- **仅开启「日文校对」**：每批最多 20 条，输入仅含 `id` 和 `text`，校对并逐条翻译，禁止合并（返回多条合并触发结构错误）。
- **仅开启「语义合并」**：每批最多 20 条，模型返回合并分组 `source` 与译文 `chinese`，App 按 `source` 范围确定性拼接原始日文（不改写原文）。
- **两者均开启**：每批最多 20 条，模型同时完成校对、语义合并与翻译。

启用「语义合并」时，合并限制为软限制，按听写模型区分：`qwen-audio-3.1-asr`（在线整句级长条目）每条合并最多 2 条、跨度最多 18 秒；其他模型最多 4 条、跨度最多 12 秒；合并后日文和中文各最多 80 个非空白字符，单条输出不限字数。App 按时间轴给出参考分组（不限制条间空隙——语义合并常跨长停顿，跨度上限已限制合并字幕覆盖的静音长度），并对自身时长或字数已超限的条目标记 `lock`，禁止模型将其与前后合并。输入只含 `id`、`group`、`text` 和可选 `lock`，不含时间戳。模型确属同一句的相邻条目可合并，参考分组内优先、确属同一句时也可跨相邻组；返回 `captions` 数组，`source` 编号连续且按顺序覆盖全部源条目，不能把一条原条目拆进两条输出。结构合法（JSON 可解析、编号连续全覆盖、不违规合并、启用校对时日文非空、中文非空）是硬要求；条数、跨度、字数、`lock` 为软限制，违规不拒绝交付，而是收集成可执行反馈。「自动修正合并格式」开关（仅在开启「语义合并」时显示，默认关闭）打开后软违规时附上一次返回与具体违规项，让模型只拆分违规组修正一次；关闭或修正后仍违规则直接交付字幕。启用任一项日文结构化选项时，每批最多 2 次请求（首次 + 一次后续：结构损坏盲目重试，或软违规定向调优），结构损坏重试后仍失败则任务失败，错误详情附具体结构原因和模型返回的裁剪片段（地址已清洗，最多 1500 字符）。服务请求失败时可在详情查看 HTTP 状态码。请求显式设置 `max_tokens`（思考开启时更高），返回被截断时错误信息单独标注。解析容忍任意位置代码围栏和前后杂文，提取首个配平 JSON 对象。

全部批次完成并校验后保存。生成字幕文件保留 `origin`、可选 `language` 和原始 `cues`，在 `revisedCues` 中保存显示用的双语结果。现有字幕的 `extra-*.json` 翻译覆盖记录原字幕文字与时间轴的 `sourceFingerprint`，匹配时才应用。旧字幕继续可读。合并条目记录 `sourceCount`；润色不再按合并条目字数硬拒绝（字数为软限制）。自动润色在保存前执行，失败时使用初译。手动润色只更新中文。

双语生成字幕支持在播放页字幕全文「更多」菜单及「已下载文件 → 字幕」预览弹窗中单独删除某一种语言（存在待发布记录或进行中任务时拒绝操作）：

- **单独删除中文字幕**：移除 `revisedCues` 并恢复原始听写 `cues`，将对应已完成 `whisper_jobs` 的 `translateStatus`、`translatedAt` 及摘要中的 `TRANSLATION` 分段重置，同时清理非活跃 `translation_jobs`，保留听写结果并允许重新翻译；外挂/B 站字幕带翻译覆盖时仅删除 `extra-*.json` 覆盖文件与非活跃翻译任务，不动原字幕。
- **单独删除原文字幕**（仅听写生成字幕）：从 `displayCues` 提取译文写入 `cues`、清除 `revisedCues` 并写入 `"language": "zh-Hans"`，保留 `origin` 与听写 `DONE` 状态；加载后不再显示翻译入口也不触发自动翻译，如需原文可重新生成字幕。


## 任务进度与摘要

`AppGraph.taskProgress` 为进程级共享实例，按 `TaskKey(kind, id, child)` 管理内存进度。任务开始生成尝试标识，传输回调另带阶段标识；旧尝试和旧阶段回调不能更新当前统计。阶段变化立即发布，字节、耗时和处理量由单一 1 秒采样器发布，无排队或运行任务时停止采样。现有 DB 字节和本机听写进度回写保留，不增加逐秒统计写库。

播放页按当前队列条目的入库曲目编号、远端音轨身份、本地路径及已加载字幕的音频指纹观察听写任务。只有字幕所属队列条目一致时才使用指纹。观察 `content:` 音频时仅推导暂存路径，匹配过程不会写入任务或复制文件。

千问文件听写依次报告上传凭证、上传、提交、远端 `PENDING` / `RUNNING` / `UNKNOWN`、取结果和保存；恢复 `remoteJobId` 时跳过上传，只统计本进程恢复后的运行段。沿用 2 秒轮询和 30 分钟超时。Qwen3-ASR 报告模型信息、上传、等待听写结果和保存，不推断服务端识别百分比。上传计数只包装文件 RequestBody，不包含 multipart 开销；重定向重发会复位逻辑位置与速率窗口，实际重发字节继续累计。

本机回调携带 `OfflineTranscriptionProgress(processedMs, totalMs, detail)`，以输入时间轴推进，SenseVoice 静音检测期间仍上报，Parakeet 双声道每个输入块只计算一次。未知总时长不显示百分比或 ETA。翻译按输入条数计算，日文开启校对或语义合并时 20 条、其余情况 40 条一批；结构重试和定向修正不重复增加完成量，当前批次计时包含后续请求。润色按有译文条目重新分批，每批 40 条；自动润色失败在摘要中标记保留初译。

数据库 20 在三张任务表增加可空 `progressSummary`，以 kotlinx.serialization 保存分段 JSON。数据库 22→23 为 `downloads`、`whisper_jobs` 和 `translation_jobs` 增加可空 `dismissedAt`，并为听写和独立翻译任务增加可空 `createdAt`；迁移不设置 SQL `DEFAULT`。数据库 23→24 新增 `track_subtitles` 曲目字幕绑定表（`trackId` 唯一外键级联删除，`fileId` 可空外键级联删除，包含 `kind`、`fileId`、`uri`、`treeUri`、`displayName`、`offsetMs`、`updatedAt`），为 `translation_jobs` 增加可空 `targetKind`、`outputFilename`，为 `whisper_jobs` 增加可空 `forceRegenerate`；三个新增可空列同样不设置 SQL `DEFAULT`，新装与升级结构一致。听写段和自动翻译段合并保存，B 站字幕为下载任务独立子段；重试听写会清空整个摘要，重试自动翻译只清除 `TRANSLATION` 分段并保留听写段的进度、耗时和结果。检查点仅在阶段和终态写入，历史 NULL 不补算耗时。启动时先恢复字幕发布，再登记中断翻译的结果；已恢复发布的摘要与最终成功或保存失败一致。摘要不保存凭证、临时媒体地址和每秒时间线。

非生成字幕的翻译及手动润色覆盖写入 `filesDir/subtitles/` 下的 `extra-*.json`，文件名按曲目身份确定（`track:`、`url:`、`path:`、`queue:` 或 B 站 `bili:`），不同来源与曲目互不覆盖。覆盖文件保存原字幕文字和时间轴的 `sourceFingerprint`，仅当当前字幕与记录一致时应用；生成字幕文件则保留 `origin` 与 `revisedCues`。

## 字幕加载与交互约束

- 字幕加载优先按已入库曲目的 `track_subtitles` 手动绑定读取（支持作品文件、外部持久授权 URI、应用内导入副本、强制生成字幕或明确关闭），无绑定时自动匹配生成字幕、作品跨目录同源字幕及受「作品跨来源借用字幕」（`crossSourceFallback`，默认开启）控制的其他来源字幕，并支持毫秒级时间轴微调（`offsetMs`）与强制重新生成（`forceRegenerate`）；未入库曲目不支持手动关联。
- 字幕按钮仅在字幕就绪、无当前句子且结果不是「没有听出人声」时显示；句间空隙不触发按钮显示。
- 字幕全文列表点击句子后跳转至句子起始时间并保留列表页；播放页当前句用于打开全文列表；顶栏菜单支持切换/选择字幕、重新生成、解除手动关联及仅删除生成字幕。
